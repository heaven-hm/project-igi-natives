## 2. Methodology

### 2.1 Trust model (the local reverse-engineering policy)
`igi2.pdb` is a *semantic dictionary only*. An IGI 2 address is never evidence.
Every accepted fact traces to igi.exe machine code; unknown is preferred over fabricated.

### 2.2 Discovery pipeline
1. **Registration-table mining** — igi.exe pushes each script-command's address *together with* its
   exact name string into its own registrar (`GAME_DEFINE_OPTIONS`, `0x004B8890` → fcn.`0x4BAAC0`;
   secondary registrars `0x4B88C0`/`0x4B88F0`). Full linear disassembly of `.text` yielded 160 sites
   → 151 unique (address, name) pairs → 158 new natives after dedup against the existing SDK.
2. **Embedded-string names** — functions whose own error messages name them
   (e.g. `"Mem_Alloc() failed to allocate %d bytes."` referenced inside the function body)
   → confirmed renames: Mem_Alloc, Mission_Open, Resource_Flush/Unload, Script_SetSymbolContext,
   AnimTrigger_ParseConfigFile, PhysicsObjType_ParseConfigFile, GameMaterial_LoadParameters,
   HumanPlayer_LoadParameters, WeaponType_Open.
3. **Registration block at 0x4156FC–0x415787** — missed by first sweep; gave Game_UpdateVolume,
   Game_DisablePlayerInput, Game_EnablePlayerInput, Game_EnableMusic, Game_DisableMusic,
   Game_CutsceneDelete, StatusMessageScreen_ClearMessages.
4. **Game-script mining** — retail `.QVM` files (MAINMENU.QVM, ingamemenu.qvm, config.qvm) reference
   natives by name; diffing those identifiers against the SDK surfaced Config_ResetGraphicOptions.
5. **Third-party corroboration** — OpenIGI C# reimplementation (param semantics, return types),
   BlanknameES/IGIPatch asm (13 named engine functions added).
